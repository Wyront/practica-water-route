# WaterRoute — База данных

## Состав

| Файл | Описание |
|------|----------|
| `schema.sql` | Создание таблиц, индексов, внешних ключей, views, триггеров |
| `seed.sql` | Демонстрационные данные (5 ролей, 25 пользователей, 3 склада, 6 товаров, 30 заказов, 8 маршрутов) |
| `procedures.sql` | ~80 хранимых процедур для всех операций приложения |
| `triggers.sql` | 8 триггеров для защиты целостности и аудита |

## Порядок развёртывания

```bash
mysql -u root -p < schema.sql
mysql -u root -p < seed.sql
mysql -u root -p < procedures.sql
mysql -u root -p < triggers.sql
```

## Важные правила

- Все обращения к БД из C# — только `CALL sp_...`. Прямых `SELECT/INSERT/UPDATE/DELETE` нет.
- Транзакции открываются только в корневых процедурах. Вложенные `START TRANSACTION` запрещены.
- Нумерация заказов/маршрутов: `WR-0001`, `R-001` через `UUID_SHORT()` + `LAST_INSERT_ID()`.
- Удаление каскадное только через процедуры. `ON DELETE CASCADE` в схеме не используется.
- Уникальность курьера/авто/диспетчера — только по активным маршрутам. Исторические записи не мешают.

## Триггеры (8)

| Триггер | Таблица | Действие |
|---------|---------|----------|
| `trg_stock_no_negative` | `warehouse_stock` | Запрет отрицательного остатка |
| `trg_stock_reserved_not_exceed` | `warehouse_stock` | Резерв ≤ физический остаток |

| `trg_delivery_full_check` | `route_stops` | `delivered` только при полном соответствии |
